NanoVDB:

  Improvements:
  - The Python nanovdb.DeviceGridHandle no longer uses the deprecated dual-space buffers, so it is ready for their removal in 14.0. Its host side is ordinary host memory, pinned in place on its first transfer so that deviceUpload(sync=False) and deviceDownload(sync=False) stay asynchronous; a handle that is only read, built or written on the host never calls CUDA. Its device side is a cuda::Buffer on the device where the grids were built or first uploaded, and every transfer and synchronization runs on that device, whatever device is current. Grids already returned to Python stay valid across transfers, and a handle constructed from a pair of host and device arrays still views them, now keeping them alive. The Python API is otherwise unchanged.

  Bug Fixes:
  - bool() of a nanovdb.GridHandle or nanovdb.DeviceGridHandle raised TypeError; it is now True when the handle holds grids.
  - nanovdb.DeviceGridHandle.deviceUpload on a handle without grids and deviceDownload before any upload exited the Python process; they now raise RuntimeError, as do CUDA errors in the handle's own copies and synchronizations. So do writing, validating and reading gridData of a handle whose grids are only on the device.
  - The nanovdb.DeviceGridHandle(cpu_t, cuda_t) constructor now raises ValueError when the arrays differ in size, are empty or are not 32-byte aligned, or when cpu_t does not hold valid grids, and rejects non-contiguous arrays; it asserted on a size mismatch and accepted the rest. gridSize, gridType and gridData raise IndexError for an index past the last grid.

  API Changes:
  - The Python nanovdb.DeviceBuffer class, which had no constructor or methods, is removed. nanovdb.tools.cuda.createLevelSetSphere, createLevelSetTorus, createFogVolumeSphere and createFogVolumeTorus take a nanovdb.HostBuffer as their buffer argument, like their nanovdb.tools counterparts, and nanovdb.io.deviceReadGrid and deviceReadGrids no longer take one.
