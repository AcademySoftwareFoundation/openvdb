OpenVDB:
  Build:
  - Added an OpenVDB CMake Config-file, so downstream projects can use
    find_package(OpenVDB CONFIG) and link against OpenVDB::openvdb.
  - Include directories of the core library targets now use build and install
    interface generator expressions, so installed targets no longer reference
    paths in the source or build tree.
  - The OpenVDB CMake Config-file provides OpenVDB::openvdb_ax through its
    openvdb_ax component, which requires LLVM.

NanoVDB:
  Build:
  - Added a NanoVDB CMake Config-file, so downstream projects can use
    find_package(NanoVDB CONFIG) and link against NanoVDB::nanovdb, which
    carries the configured NANOVDB_USE_* definitions and dependencies. The
    OpenVDB Config-file provides OpenVDB::nanovdb through its nanovdb component.
  - Standalone NanoVDB builds now install headers to the CMAKE_INSTALL_PREFIX
    include directory instead of /nanovdb.
  - NanoVDB::nanovdb adds --extended-lambda to CUDA sources compiled with nvcc,
    which NanoVDB's CUDA headers require.
  - nanovdb/putil/IO.h, the PNanoVDB file I/O helpers, is now installed.
  - With NANOVDB_USE_CUDA=ON, NanoVDB uses the CUDA toolkit's CCCL and clones
    CCCL only when the toolkit has none or NANOVDB_FETCH_CCCL=ON. NanoVDB
    requires CUDA 12.0 and CCCL 2.8 or newer, and the CMake Config-file
    accepts any CCCL that meets that minimum.
  - NanoVDB::nanovdb sets the NANOVDB_INCLUDE_DIR target property to the
    directory holding the nanovdb/ headers.
  - NCCL support in cuda/DeviceMesh.h is now opt-in through the new
    NANOVDB_USE_NCCL option (default OFF). NanoVDB used to enable it whenever
    it found NCCL, which made NCCL a hard dependency of the installed config.
    Builds that need DeviceMesh::comm() must now set -DNANOVDB_USE_NCCL=ON.
  - NanoVDB::nanovdb no longer adds -arch=sm_75 to consumers' CUDA sources
    when CMAKE_CUDA_ARCHITECTURES is OFF, so projects that choose their own
    architecture flags, such as PyTorch extensions, keep them.
