NanoVDB:

  New Features:
  - The point-set overloads of nanovdb::tools::cuda::pointsToGrid and voxelsToGrid have resource forms, (sets, stream, resource), like the single-set overloads: each set's grid, the merged result and all internal scratch allocate through the given resource, on the given stream, and the result is a GridHandle<cuda::Buffer<std::byte, ResourceT>> (DeviceResource by default). As for the single-set overloads, a cudaStream_t argument selects the resource form, and a literal 0 in that position fails to compile with a message saying to write cudaStream_t(0). An empty list of sets yields an empty handle, and a set without points contributes an empty grid.

  Bug Fixes:
  - nanovdb::tools::cuda::pointsToGrid with PointType::Default failed to compile for pointer-to-const point coordinates, e.g. const Vec3f*.
  - nanovdb::tools::cuda::pointsToGrid, voxelsToGrid, the PointsToGrid builder (getHandle, build) and DistributedPointsToGrid launched a zero-block kernel for a point count of zero, which exited the process; they now return a valid empty grid, as MeshToGrid and the topology tools do for an empty input.
  - nanovdb::tools::cuda::updateChecksum with CheckMode::Full exited the process on an empty grid; it now computes the same checksum as the host.
  - nanovdb::cuda::mergeGridHandles of no grids and nanovdb::cuda::copyTo of an empty handle now return an empty handle for single-space buffer types (cuda::Buffer) when given a prototype buffer, instead of throwing for buffers over a resource that cannot be default-constructed.
  - A stream type that converts to cudaStream_t and is not a buffer, such as a framework's stream wrapper, now selects the resource form of the GPU tools instead of being deduced as the prototype buffer and failing to compile.
  - nanovdb::tools::isValid and checkGrid with CheckMode::Full failed an assertion in debug builds on a grid with no nodes.
  - nanovdb::tools::cuda::PointsToGrid<Point>::setPointType, and so pointsToGrid, now reject PointType::Disable with std::invalid_argument before building anything; it used to throw std::runtime_error after the grid was allocated.
  - Point grids built with PointType::Disable, as DistributedPointsToGrid<Point> builds them, no longer report a blind-metadata entry that was never allocated.
  - The DistributedPointsToGrid constructors now reject a singular or non-finite map with std::invalid_argument, as PointsToGrid does.
  - nanovdb::util::cuda::blockedCRC32 of zero bytes now matches the host (~0).
