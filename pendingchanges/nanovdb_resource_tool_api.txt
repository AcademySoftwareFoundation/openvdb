NanoVDB:

  New Features:
  - The GPU tools gain resource forms beside their prototype-buffer forms, which are unchanged (CUDA). voxelsToGrid, both single-set pointsToGrid overloads, indexToGrid and addBlindData take (..., stream, resource): one memory resource, held by value (pass a cuda::ResourceRef to borrow), allocates both the scratch and the output, which is a GridHandle<cuda::Buffer<std::byte, R>>. Passing a cudaStream_t selects the resource form, so existing calls resolve as before; a literal 0 where the stream goes selects the prototype form, which now fails to compile with a message to write cudaStream_t(0).
  - The builder classes PointsToGrid, DilateGrid, MergeGrids, PruneGrid, RefineGrid, CoarsenGrid, MeshToGrid and IndexToGrid gain build() beside getHandle(buffer) (and MeshToGrid buildWithUDF() beside getHandleAndUDF()): the output allocates through the builder's own resource, on its stream, as a handle over cuda::Buffer<std::byte, ResourceRef<R>> that borrows it.

  Bug Fixes:
  - addBlindData drew its scratch only from the default instance of its resource type, so a resource without a default constructor, such as a ResourceRef, could not drive it; the new resource form takes the resource explicitly (the prototype form still uses the default instance).
  - addBlindData copied the blind-data name into its 256-byte field unchecked, overflowing the host stack for longer names; a null or too-long name, a null grid, or null data with a nonzero count now throws std::invalid_argument.
