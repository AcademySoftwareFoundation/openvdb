NanoVDB:

  New Features:
  - Every built-in CUDA memory resource (DeviceResource, MallocResource, PinnedResource, ManagedResource, and AsyncFromSync<R> when R has it) now provides operator== and operator!=, as CCCL's cuda::mr resource concepts require: instances compare equal when memory allocated through one may be deallocated through the other. The stateless resources always compare equal; AsyncFromSync compares its wrapped resources. The new trait nanovdb::cuda::is_equality_comparable_resource detects operator==.
  - nanovdb::cuda::Buffer::resize(stream, count) resizes a buffer over a stream-ordered resource with the stream first, matching the (stream, resource, count, noInit) constructor and cuda::buffer's constructors.

  API Changes:
  - nanovdb::cuda::ResourceRef<R>::operator== now also compares the referenced resources when R provides operator==, as cuda::mr::resource_ref does; previously it compared only their addresses. Refs to two distinct instances of a stateless resource now compare equal, since memory allocated through either may be deallocated through the other.
  - nanovdb::cuda::Buffer::resize(count, stream) is deprecated in favor of resize(stream, count), and will be removed in 14.0. It accepts the same counts as before.
  - nanovdb::cuda::Buffer rejects an element count whose byte size exceeds PTRDIFF_MAX with std::runtime_error, in its constructors and both resize orders, so a negative count converted to size_t throws instead of reaching the allocator.
  - Using a CUDA memory resource without operator== is deprecated: constructing a ResourceRef over it warns on the caller's line, and a cuda::Buffer, TempPool or GPU builder over it warns once per resource type, from within the NanoVDB headers (so a build that includes NanoVDB as a system header may not show that second form). 14.0 makes equality part of the resource concepts, as CCCL's cuda::mr concepts do. A stateless resource adds friend bool operator==(const R&, const R&) { return true; }.
