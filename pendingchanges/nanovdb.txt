NanoVDB:

  New Features:
  - Implemented the Half grid type, previously a placeholder, including tools::createNanoGrid conversion. The voxel type is the raw 16-bit storage type, so no particular float conversion is imposed.
  - The GPU tools (voxelsToGrid, pointsToGrid, indexToGrid, createNanoGrid, addBlindData) gain resource forms beside their prototype-buffer forms, taking (..., stream, resource) (CUDA). One memory resource, held by value and defaulting to default_resource<R>(), allocates both scratch and output, which is a GridHandle<cuda::Buffer<std::byte, R>>; pass a cuda::ResourceRef to borrow an instance. A cudaStream_t argument selects the resource form, so existing calls resolve as before.
  - The builder classes (PointsToGrid, DilateGrid, MergeGrids, PruneGrid, RefineGrid, CoarsenGrid, MeshToGrid, IndexToGrid) gain build() beside getHandle(buffer), and MeshToGrid gains buildWithUDF(): the output allocates through the builder's own resource on its stream, as a handle over cuda::Buffer<std::byte, ResourceRef<R>>.
  - nanovdb::cuda::mergeGridHandles and splitGridHandles accept single-space device handles, taking (handles, stream, proto). The result allocates through the prototype's resource and is complete when the call returns. nanovdb::mergeGrids and splitGrids accept host-accessible single-space handles, e.g. over cuda::PinnedResource.
  - Added GridHandle::adopt(buffer, metadata) and GridHandle::metaData(), the public way to wrap bytes whose grid layout the caller already knows. adopt validates only the layout arithmetic (contiguous, NANOVDB_DATA_ALIGNMENT-aligned grids within the buffer) and trusts the grid types.
  - Every built-in CUDA memory resource (DeviceResource, MallocResource, PinnedResource, ManagedResource, AsyncFromSync<R>) provides operator==/!=, equal when memory from one may be freed through the other. The new trait nanovdb::cuda::is_equality_comparable_resource detects it, and ResourceRef<R>::operator== now compares the referenced resources rather than only their addresses.
  - Added nanovdb::cuda::Buffer::resize(stream, count), stream first, matching the constructor order.

  Improvements:
  - Refactored math::Mat and math::Vec onto shared MatBase/VecBase base classes, giving every type a complete operator surface, bounds-checked element access and constexpr evaluation throughout Math.h and the Map API. The cross-template Vec conversion constructors are now explicit, so implicit Vec conversions may need a cast, and the scalar-times-Vec/Mat operators are hidden friends, so a fully qualified math::operator*(2.f, v) must be rewritten. Added opt-in over-aligned math::Vec2Aligned/Vec3Aligned/Vec4Aligned; grid layouts and the file format are unchanged.
  - The Python nanovdb.DeviceGridHandle is now backed by single-space buffers, ready for the dual-space buffers' removal in 14.0. Its host memory is pinned on first transfer so async upload/download stays asynchronous, a host-only handle never calls CUDA, and its device side lives on the device where the grids were built or first uploaded. The Python API is otherwise unchanged.
  - Every public CUDA header now compiles as the first include of a translation unit (e.g. nanovdb/cuda/HandleStorage.h or tools/cuda/GridStats.cuh no longer require nanovdb/cuda/GridHandle.cuh first).

  Deprecations:
  - GridHandle::deviceUpload/deviceDownload/deviceData(int), NodeManagerHandle::deviceUpload/deviceDownload, and the same members of cuda::DualDeviceBuffer and cuda::DualUnifiedBuffer are deprecated, to be removed in 14.0 with the dual-space buffers. In 14.0 the GPU tools build into the device-only GridHandle<cuda::Buffer<std::byte>> by default, so these warnings also reach code that transfers grids through the default buffer type. Use cuda::copyTo to move handles between host and device, cuda::createNodeManager on the device, and cuda::Buffer<std::byte, cuda::ManagedResource> or one handle per GPU for multi-GPU handles. The Python DeviceGridHandle's deviceUpload/deviceDownload are unchanged.
  - The dual-space overloads of cuda::mergeGridHandles/splitGridHandles and the older nanovdb::mergeDeviceGrids/splitDeviceGrids are deprecated: hold grids in GridHandle<cuda::Buffer<std::byte>> and use the single-space overloads.
  - Using a CUDA memory resource without operator== is deprecated; 14.0 makes equality part of the resource concepts. A stateless resource adds friend bool operator==(const R&, const R&) { return true; }.
  - cuda::Buffer::resize(count, stream) is deprecated in favor of resize(stream, count), to be removed in 14.0.
  - cuda::detail::HandleFactory is deprecated in favor of GridHandle::adopt/metaData. It previously applied no checks; a layout adopt rejects, such as a grid at a non-NANOVDB_DATA_ALIGNMENT offset, now throws std::runtime_error.

  API Changes:
  - The Python nanovdb.DeviceBuffer class, which had no constructor or methods, is removed. nanovdb.tools.cuda.createLevelSet*/createFogVolume* take a nanovdb.HostBuffer like their nanovdb.tools counterparts, and nanovdb.io.deviceReadGrid/deviceReadGrids no longer take a buffer.
  - The GPU tools validate arguments before allocating or launching, throwing std::invalid_argument for a null grid, a null or over-long blind-data name, a negative point count, a non-positive voxel size or density target, or a singular or non-finite map. PointsToGrid::setPointType rejects PointType::Disable the same way instead of throwing std::runtime_error after allocation.
  - cuda::Buffer throws std::runtime_error for an element count whose byte size exceeds PTRDIFF_MAX.
  - mergeGrids and splitGrids throw if a grid header's size disagrees with the handle metadata, and cuda::mergeGridHandles throws before allocating if any grid but the last is not a multiple of NANOVDB_DATA_ALIGNMENT.

  Fixes:
  - tools::cuda::PointsToGrid now pads the point blind data to NANOVDB_DATA_ALIGNMENT when sizing a Point grid. A payload that was not a multiple of 32 bytes (e.g. PointType::Voxel8 or Voxel16) left the next grid in a merged buffer misaligned, which faulted on the device. Such grids are larger by the padding, so their serialized bytes differ from files written before this fix.
  - The point-set overloads of tools::cuda::pointsToGrid and voxelsToGrid failed to compile for every buffer type; pointsToGrid(points, pointCount, voxelSize, type, buffer, stream) was declared but never defined; and pointsToGrid with PointType::Default did not accept pointer-to-const coordinates.
  - A point count of zero no longer exits the process in pointsToGrid, voxelsToGrid, the PointsToGrid builder or DistributedPointsToGrid; they return a valid empty grid.
  - Empty grids are handled consistently: tools::cuda::updateChecksum (CheckMode::Full) and util::cuda::blockedCRC32 now match the host, tools::isValid and checkGrid no longer fail a debug assertion on a grid with no nodes, and cuda::mergeGridHandles of no grids and cuda::copyTo of an empty handle return an empty handle.
  - tools::cuda::addBlindData overflowed the host stack for blind-data names longer than 256 bytes, and could not be driven by a resource without a default constructor such as a ResourceRef.
  - Point grids built with PointType::Disable no longer report a blind-metadata entry that was never allocated.
  - A stream wrapper type that converts to cudaStream_t now selects the resource form of the GPU tools instead of failing to compile.
  - Python: bool() of a GridHandle or DeviceGridHandle raised TypeError and is now True when the handle holds grids. DeviceGridHandle transfers on a handle without grids, CUDA errors, and host access to device-only grids raise RuntimeError instead of exiting the process. The DeviceGridHandle(cpu_t, cuda_t) constructor raises ValueError for mismatched, empty, misaligned, non-contiguous or invalid arrays, and the per-grid accessors raise IndexError for an index past the last grid.
  - Fixed math::Min/Max for 32-bit integers routing through fminf/fmaxf, which lost precision above 2^24 and could overflow near INT_MAX.
  - Fixed integer division in the Vec and Mat scalar operator/, which computed a reciprocal first (Vec3i(6,8,10) / 2 returned (0,0,0)), and the Vec scalar operator*= when the scalar aliases one of the vector's own components.
  - Fixed Mat2::inverse returning uninitialized values on singular input (now zero), and Vec2 arithmetic against Coord silently dropping the z component (the overloads now take Coord2).
  - Fixed math::Round(Vec3<float>) disagreeing with the double overload at half-integers, and Vec2/Vec3::round() moving some floats to the wrong integer. They and the new scalar math::Round(float/double) now round exactly to the nearest integer, halfway cases toward +inf.
