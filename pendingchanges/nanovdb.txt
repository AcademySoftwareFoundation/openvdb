NanoVDB:

  New Features:
  - Added nanovdb::math::isoCrossing, a _hostdev_ function that intersects a ray against a user-defined iso-surface.
  - Added doc/nanovdb/TEACHME, an interactive tutorial for the NanoVDB user API designed to be taught by an LLM coding agent. Includes a cheat sheet, a GPU ray-marching capstone, and a CI harness that compiles every code block against the NanoVDB headers so the tutorial cannot drift from the API.
  - Added a new resource-aware buffer family for single-space (device-only or host-only) allocations: nanovdb::cuda::Buffer/BufferView allocate from an injectable memory resource and free on their retained stream, and nanovdb::cuda::ManagedResource is a cudaMallocManaged-backed resource exposing both host and device accessors over one allocation, the migration target for UnifiedBuffer users. GPU tool entry points can now return either buffer family via a new bridge header, nanovdb/cuda/HandleStorage.h.
  - Added nanovdb::cuda::copyTo, an explicit stream-ordered transfer between grid handles in different address spaces (device-to-host-readable and device-to-device across resources), callable directly from host-only code since it adopts the source's already-validated metadata.
  - Added ReadAccessor::getDimAndActive(), which returns the ray-aware traversal step size and voxel active state in a single tree descent. ActiveExact and ActiveOnLeafOnly policy tags trade exactness for a cheaper leaf-only query, packed into 32 bits to reduce register pressure.

  Improvements:
  - Most GPU tools (TopologyBuilder and its consumers DilateGrid/MergeGrids/PruneGrid/RefineGrid/CoarsenGrid, MeshToGrid, indexToGrid, updateGridStats, signedFloodFill, addBlindData, DistributedPointsToGrid, PointsToGrid, createNodeManager/GridStats) now allocate their device scratch through a defaulted, injectable ResourceT template parameter instead of hand-paired allocate/free calls, so existing code is unaffected. New adapters support this: nanovdb::cuda::SyncFromAsync/AsyncFromSync bridge between synchronous and stream-ordered resource concepts, ResourceRef is a non-owning reference to a resource, and MallocResource is a synchronous cudaMalloc-backed fallback for devices without memory-pool support.
  - nanovdb::GridHandle and NodeManagerHandle can now manage a single-space buffer (e.g. GridHandle<cuda::Buffer<std::byte, R>>): device-only buffers parse metadata and deep-copy through the device, while host-accessible resources (e.g. PinnedResource) behave as host-readable single-space handles. GridHandle::reset, NodeManagerHandle::reset and tools::VoxelBlockManager::reset now release storage via the buffer's destroy() when available; cuda::Buffer::clear/BufferView::clear are deprecated in its favor.
  - CNanoVDB gained integer (I) grid support, setValue methods to write voxels, and getLeaf methods to acquire raw leaf pointers.
  - nanovdb::Mask is now trivially copyable: its copy constructor is defaulted instead of hand-duplicating the memberwise copy.
  - Several CUDA kernels were rewritten for better parallelism: GridChecksum's CRC32 now uses a slicing-by-4 table lookup with an associative GF(2) combine (17x faster, bit-identical); GridStats uses cooperative warp/block reductions instead of one thread per node; IndexToGrid's node/leaf remapping is now cooperative and coalesced.
  - cuda::DeviceBuffer::orderAfterPriorUses is now public, the consume-side companion of recordUse, letting external consumers (e.g. zero-copy array-interface exports) order their stream after the buffer's tracked uses.
  - Replaced the CUDA VoxelBlockManager inverse-map decode's O(nLeaves x 512) per-block sweep with an O(1)-per-slot select, giving byte-identical decode maps that are ~2x faster (see API Changes).
  - Added the CMake option NANOVDB_CUDA_WERROR (default ON, also implied by OPENVDB_CXX_STRICT), which passes --Werror=all-warnings to NVCC so device-side diagnostics fail the NanoVDB tests/tools/examples build.

  API Changes:
  - The VoxelBlockManager decode is now built around decodeInverseMap, a thread-local primitive that decodes one slot into registers with no shared memory or synchronization. The cooperative decodeInverseMaps keeps its old signature as a thin wrapper; computeBoxStencil now takes the decoded (leafIndex, voxelOffset) by value instead of shared-memory arrays.

  Deprecations:
  - nanovdb::cuda::DeviceBuffer is deprecated in favor of the single-space nanovdb::cuda::Buffer plus explicit nanovdb::cuda::copyTo transfers. Only code naming DeviceBuffer directly is warned; the GPU tools' default buffer type (now the transitional DualDeviceBuffer) is unaffected until removal.
  - nanovdb::cuda::UnifiedBuffer is deprecated in favor of nanovdb::cuda::Buffer<std::byte, cuda::ManagedResource>, whose GridHandle exposes the same host/device accessors over one managed allocation. Standalone managed allocations should use explicit util::cuda::memAdvise/memPrefetchAsync in place of the old advise/prefetch members.

  Fixes:
  - Fixed an out-of-bounds device read in SignedFloodFill's root-tile scanline pass, where child-node lookups resolved against a truncated host copy of the root instead of the real device root. Only manifested for grids with multiple non-adjacent root children on the same z-scanline.
  - Fixed DilateGrid and signedFloodFill launching kernels on the default stream instead of the caller's stream, corrupting output on non-blocking streams.
  - Fixed a cross-device race in DistributedPointsToGrid: device segment boundaries were rebalanced by adjusting only adjacent pairs, which cannot consolidate a tile spanning three or more GPUs and let multiple devices race on the same leaf's value mask. Boundaries are now snapped globally and monotonically to tile boundaries so every leaf is owned by exactly one device.
  - Fixed cuda::DeviceBuffer freeing device memory without ordering the free after outstanding work on non-blocking streams; each allocation now tracks its uses with an event. recordUse itself now chains uses across streams so the single tracking event transitively covers every recorded use, not just the most recent.
  - Fixed nondeterministic output and a host-heap over-read (when copying grid names) in the CUDA PointsToGrid, DistributedPointsToGrid, IndexToGrid and MeshToGrid tools.
  - Fixed an out-of-bounds device read and host stack corruption in tools::cuda::evalChecksum.
  - addBlindData and indexToGrid now normalize the output grid's index/count fields (mGridIndex=0, mGridCount=1); both copy the source header, so a source taken from a multi-grid buffer used to leave a stale index/count corrupting the output handle's metadata parse.
  - Fixed a caching bug in nanovdb::ReadAccessor<LEVEL0,LEVEL1,LEVEL2> (e.g. <0,1,2> or <0,1>): it now caches nodes at all requested levels, matching openvdb::ValueAccessor, instead of only leaf nodes, also improving random-access performance in some cases (especially on the CPU). Restore the old behavior via -DNANOVDB_USE_OLD_ACCESSOR=ON if needed.
  - createNodeManager now synchronizes the stream before reading back the device-computed NodeManager size, instead of relying on an unordered read that happened to work only for pageable-memory copies.
  - Fixed GridHandle read seek-offset over-counting for handles containing multiple grids.
  - Fixed tools::cuda::MeshToGrid leaving the CALL_CUBS macro defined past the end of its header, unlike its sibling CUDA tools.
  - Fixed six public headers missing from nanovdb/CMakeLists.txt's install lists (cuda/Buffer.h, cuda/PinnedResource.h, math/Proximity.h, tools/cuda/MeshToGrid.cuh, util/MaskPrefixSum.h, util/cuda/Rasterization.cuh), which broke builds against an installed NanoVDB.
  - Fixed two nvcc diagnostics in header-defined CUDA kernels: GridStats's __shared__ statistics arrays now use constructor-free storage (cub::Uninitialized, since CUDA forbids dynamic initialization of __shared__ variables), and GridChecksum's CRC32 kernels are now static instead of inline (ignored for __global__ functions).
  - Deprecated nanovdb::math::ZeroCrossingNode and renamed it nanovdb::math::zeroCrossingNode to follow naming convention.
  - Fixed three CNanoVDB issues: local kernel methods needed static, auto-computed reserved sizes were replaced with hard-coded ones (C99 forbids zero-sized arrays, crashing some compilers), and accessor key values are now initialized at construction (previously undefined, putting some compilers into a bad state).
