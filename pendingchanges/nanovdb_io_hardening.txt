NanoVDB:

  Fixes:
  - The NanoVDB file and raw-stream readers no longer trust sizes and names read from their input. Grids smaller than their headers, grid names without NULL termination, Blosc chunks that claim more bytes than were read, file or grid sizes that wrap a stream offset or a 64-bit byte count, and sizes larger than the bytes left in the stream now throw std::runtime_error. The uncompressed size of a compressed grid cannot be checked before it is allocated, so a corrupt one can still raise std::bad_alloc.
  - A file or raw stream that ends inside a grid now throws std::runtime_error, including from io::readGridMetaData, io::hasGrid, and lookups that would otherwise report a missing grid. Raw-stream reads of a single grid no longer return a handle over uninitialized memory when the stream ends inside that grid, and a lookup by name or index no longer returns a grid stored after the end of the raw buffer.
  - io::readGridMetaData, io::readGrid, nanovdb_print and nanovdb_validate no longer hang on a stream shorter than a grid header (672 bytes), such as an empty or truncated file. An empty stream reads as zero grids, and a partial file header throws std::runtime_error. A read that reaches the end of a file stream now leaves the stream in a good state, where it previously left eofbit set. A read error, or a stream that cannot seek back after the readers probe it for a raw grid buffer, now throws std::runtime_error instead of ending the read early or hanging.
  - tools::crc32Head, and so updateGridCount and validateChecksum, no longer read past a grid written before v32.7.0 that has no upper nodes, such as an empty grid.
  - Moving a zero-size HostBuffer no longer leaves a dangling pointer in its pool's register.
